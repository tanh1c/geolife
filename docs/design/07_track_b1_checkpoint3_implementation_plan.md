1. **RED contract tests (Moto/local only):** new POST attempts one best-effort `accepted` event after successful SQS send; retry/conflict do not. A first-send failure followed by successful idempotent retry may undercount acceptance; regression test this limitation without inventing a durable outbox. The first conditional lease persists epoch `first_lease_at_ms` captured after receive but before the successful write; failed lease writes emit no lease event, second/duplicate deliveries do not rewrite it. Success and terminal failure persist a pre-write `terminal_at_ms` and emit the terminal event only after the conditional write succeeds; failed writes and duplicates produce no completion event. Retry emits one best-effort attempt failure even when the fallback state write fails; only a successful conditional terminal write emits `failed`, and a failed fallback remains a job-state concern rather than a telemetry success claim. Test subsecond timestamps, missing/negative cross-process durations on clock skew, worker monotonic runtime, TTL seconds unchanged, bounded fields and no exception/GPS/token labels. Keep existing HTTP metrics endpoint privacy tests.

No worker Prometheus visibility through API; worker restart resets memory. Event emission best-effort after state writes; telemetry failure is surfaced in local test recorder diagnostics, never changes job state. No CloudWatch publisher or fake durable counters. Keep existing S2b API and CP1/CP2 behavior.
